# Token Crawl

A web text-adventure dungeon crawler where **every piece of game content is
LLM-generated the first time any player observes it, then permanently cached** —
so all crawlers experience the same deterministic, designed-feeling world.
Permadeath, a leaderboard, death echoes, free re-rolls. Dungeon Crawler Carl energy.

- **Floor 1 is hand-written** (`floors/floor-01.md`) — the seed that sets the tone.
  Every floor below it is written by the AI on the first descent and cached, so the
  dungeon has no bottom. Code decides what each floor is pitched at from its depth;
  the AI only writes the place.
- **One scale table** (`app/models/scale.py`) anchors every number in the game: what
  a balanced character has at each level, what an enemy of that level is worth, and
  what gear and gold cost there. Difficulty and prices climb by depth off that one
  table rather than being restated per floor.
- Areas, enemies, drop tables, items, classes, abilities, shops, and even the
  *rulings for freeform actions* ("pry the gem from the altar") are generated
  just-in-time and cached forever. Drop tables generate their **slots** on first
  kill, but each slot's item only when a roll first lands on it.
- Three-tier action pipeline: keyword fast path (free) → cheap parser/gatekeeper
  model (blocks prompt injection with cheeky quips) → deterministic rules engine
  (no LLM) → generation model for genuinely novel actions.
- The LLM authors **data, never code** — a typed effect system interpreted by the
  engine. Rate limits keep the API key safe from financial DoS: 10 actions a second
  per session, and one *generating* action a second — one player action is one
  trigger however many model calls it makes.

## Run it

```bash
uv sync --extra dev

# Offline dev mode (fixture backend, no API key, no network):
LLM_BACKEND=fixture uv run uvicorn app.main:app --reload

# Real mode:
cp .env.example .env      # add your OPENROUTER_API_KEY
uv run uvicorn app.main:app
```

Open http://127.0.0.1:8000, describe your crawler, and type actions:
`north`, `attack goblin`, `take shiv`, `equip pipe`, `buy 2`,
`pry the gem out of the altar`, `pick up the table`…

## Models (OpenRouter)

Everything goes through [OpenRouter](https://openrouter.ai)'s OpenAI-compatible
endpoint, in two tiers set in `app/config.py` (override with `PARSER_MODEL` /
`GEN_MODEL` in `.env`):

| Tier | Default | Price in/out per Mtok | Why |
|---|---|---|---|
| **A — parser / gatekeeper** | `google/gemini-2.5-flash-lite` | $0.10 / $0.40 | High volume, latency-critical. All 5 of its endpoints support structured outputs, and it has no mandatory reasoning stage. ~$0.10 per 1,000 LLM-routed actions — and the keyword fast path handles ~80% of commands for free. |
| **B — world gen / adjudication** | `google/gemini-2.5-flash` | $0.30 / $2.50 | Quality-sensitive: this content is cached forever. All 7 endpoints support structured outputs. A full 7×7 floor lands well under $1. |

Because a whole floor costs less than a coffee, **pick tier B on prose, not price**:

```bash
uv run scripts/models.py compare              # same area, generated by each candidate
uv run scripts/models.py compare --kind enemy # same, for a stat block + budget adherence
```

Good alternatives (one-line `.env` change): `moonshotai/kimi-k2.6` (strongest prose
reputation, 21/21 endpoints clean), `x-ai/grok-4.3` (most irreverent), `z-ai/glm-5.2`
(cheapest), `anthropic/claude-sonnet-5` (~$1.30/floor).

### Structured outputs, and why validation is still client-side

OpenRouter enforces `response_format` **per provider endpoint**, not per model —
some providers guarantee schema compliance, others treat the schema as a strong
hint, and by default OpenRouter will happily route to an endpoint that ignores the
parameter entirely and returns prose. So the app:

1. sends `provider.require_parameters: true`, excluding endpoints that don't honor it;
2. converts Pydantic models to a strict-mode-safe schema (`app/gen/schema.py`) —
   `oneOf`→`anyOf`, `allOf` flattened, everything `required`, `additionalProperties:
   false`, and unportable keywords (`pattern`, `maxLength`, `default`) stripped but
   preserved as prose in each field's `description`. Numeric bounds are *kept*, since
   both the OpenAI and Gemini subsets support them;
3. parses defensively (markdown fences, prose padding) and validates against the real
   Pydantic model, retrying once with the error fed back. That covers integrity only —
   balance is never enforced. The scale table goes into the prompt as a reference and
   whatever comes back is kept; an out-of-depth horror is the fun, not a fault.

Check endpoint support any time:

```bash
uv run scripts/models.py check --all    # no API key required
```

### Cost control

What actually keeps spending down is the cache: content is generated once, ever, and
every later crawler who sees it pays nothing. Cached play makes zero LLM calls.

On top of that, `app/security/limits.py` holds two rate limits, both per session and
both aimed at scripts rather than players:

- **10 actions a second.** Refused past that; no human types that fast.
- **One generating action a second.** The unit is the ACTION, not the calls under it:
  walking into an unexplored room may cause one call or fifty and counts once either
  way. When it's hit the player waits — there is no rejection path, because a brief
  pause is invisible where a refusal reads as the game breaking.

There are no per-minute limits and no daily spend cap. Both break the game for a real
player before they inconvenience anyone abusing it.

`usage.include` returns OpenRouter's **actual** cost per call, so `llm_calls.cost_usd`
is real dollars rather than an estimate — spending is observable rather than capped.

Measured on a real session: **$0.0091 for a full character creation + 4 areas + 2 enemy stat
blocks + 3 items + 1 adjudication.** Generation runs ~$0.0012/area, so a complete 7×7
floor is roughly **$0.13** — and it's paid exactly once, ever. Tier-A parses are
~$0.00006 each.

> **Prompt caching is currently a no-op here.** The floor-brief prefix is ~900 tokens,
> just under Gemini's 1,024-token minimum for implicit caching, so `cache_read_tokens`
> comes back 0. It'll start paying off on its own as floor briefs get richer. Not worth
> padding artificially to chase ~25% of the input cost on a $0.13 floor. Related calls
> still share a `session_id` so a generation burst stays pinned to one provider, which
> is what makes caching work once the prefix does cross the threshold.

Every call — including failures and their reason — lands in `llm_calls`:

```sql
SELECT kind, model, cost_usd, cache_read_tokens, ok, error FROM llm_calls ORDER BY id;
```

## Tests

```bash
uv run pytest            # offline suite, zero API calls, zero network
uv run pytest -m live    # live smoke tests (needs OPENROUTER_API_KEY, costs cents)
```

The offline suite covers the concurrency claim protocol, a scripted end-to-end
playthrough, the strict-schema converter, and every OpenRouter retry path (schema
violation, budget violation, truncation, rate limit, 4xx) over mocked HTTP.

## Architecture

Single uvicorn worker, FastAPI + HTMX, SQLite used as a K:V world cache with a
first-write-wins claim protocol (UNIQUE constraints + threading locks + stale-claim
reclamation). See `app/schema.sql` for the contract and `app/gen/locks.py` for the
claim protocol. Every LLM call is logged to `llm_calls` with real cost.

**Run with `--workers 1`.** Not a performance note — a correctness one.

One process is already parallel: FastAPI runs plain `def` handlers on a thread pool,
so players are served side by side without extra workers. SQLite ties us to one
machine anyway.

Two rules depend on there being one process, both enforced by locks held in memory:

- **One turn at a time per crawler** (`app/engine/state.py`). A turn reads the whole
  run, changes it, and writes it back, so two overlapping turns on one crawler would
  each read the same starting numbers and the second write would erase the first —
  spend the same 100 gold eight times and keep all eight purchases. Turns for one
  crawler queue; different crawlers never wait on each other.
- **One generation per cache key** (`app/gen/locks.py`). The DB claim rows keep a
  second process from generating the same room twice, but it will duplicate in-flight
  waits.

Adding worker processes means moving the turn lock into the database, the way the
generation claims already work.
